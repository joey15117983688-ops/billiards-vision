# 台球视觉识别系统——第二阶段：彩色灯光抗干扰与识别可靠性开发任务书

> **交付对象：Codex**
> 项目：`billiards-vision`
> 仓库：https://github.com/joey15117983688-ops/billiards-vision
> 开发依据：`main` 分支截至 2026-10-21 提交 `5e160603bbd0b5c90b0734236a9a1e1d2274e215`；`docs/ENGINEERING_BASELINE.md`
> 目标：在不训练模型、不接入新摄像头硬件的前提下，提升**现有本地视频**在不同台呢颜色、彩色灯光、局部阴影、反光和曝光变化下的定位与入袋判断可靠性。

---

## 0. 总体决策

本阶段只做 **光照鲁棒性 + 判定安全性**，不追求“任意画面都必须识别成功”。

**三条不可打破的规则：**

1. **几何与光照分离**：摄像头、球桌没有移动时，灯光变色不能自动改变原有球桌四角、六袋口、物理坐标与保存的校准基准。
2. **观测与猜测分离**：在光照不足、过曝或遮挡时，不能将预测位置当成实际看见的球；不能因为球在坏帧中消失就确认进球。
3. **正常场景不退化**：所有新增处理均需要对照第一阶段性能和回归结果，保证已有正常绿色、蓝色台呢素材不出现明显的定位退化、误判和卡顿。

**本阶段明确不做：**

- 考题、画圈迭代、评分、评级、球员档案；原有考题代码保持不变。
- YOLO 标注、训练、微调、更换权重；不引入新的视觉神经网络。
- 海康设备采购、实时摄像头 SDK/RTSP 接入主界面；继续使用现有本地视频测试。
- 全量重写 `main.py`、更换 PyQt5、改变现有视频播放架构。
- 通过扩大 HSV 范围来强行接受所有画面；不能以增加误检换取“识别率”。

**执行方式：以下五个子任务依次开发；每完成一个，运行相关测试、输出结果并停止，等待确认后进入下一个。**

## 1. 已知代码基础与实际风险

| 文件 / 模块 | 当前实现与风险 | 本阶段期望 |
|---|---|---|
| `src/cloth_region.py` | 采用全局 HSV 主色、颜色连通域恢复台呢及同色边条；彩色灯光可能让同一台面出现多个色域 | 改善局部光照下的台呢范围判定；不能让彩灯光斑牵引边界 |
| `src/vision/pocket/table_detector.py` | 使用 HSV 范围、轮廓、边线和四边形几何定位 | 保留结构约束；新增候选不应仅因颜色匹配而被接受 |
| `src/vision/pocket/pocket_validator.py` | 依赖局部台呢颜色和袋口暗腔/纹理/几何证据 | 对彩灯及局部过曝给出可信/不可见状态；不能把黑球或阴影认成袋口 |
| `src/camera_alignment.py` | 基于固定参考画面的灰度光流与 ORB 对齐；对齐失败会保留当前变换 | 区分光照变化与真实机位变化；失效时禁止基于旧几何确认新进球 |
| `src/vision/pocket_event/pixel_observer.py` | 使用当前帧的 HSV 主色、饱和度和亮度差寻找球体并分类 | 针对局部光照变化降低漏检和黑白球误分；保持“实测”与“推测”区分 |
| `src/vision/pocket_event/adapter.py` | `clear_scene()` 使用 HSV/肤色启发式判断遮挡；协调球体观测和入袋事件 | 彩灯不能直接等同于手臂遮挡；光照不可用时不触发进球确认 |
| `src/vision/pocket_event/pocket_event_engine.py` | 多帧进球状态机；依赖观测连续性和 `scene_clear` 等信息 | 在画质或几何状态不可靠时明确抑制 `POTTED`，记录原因 |
| `main.py` | 现有校准、摄像机对齐、逐帧观察和 UI 状态管理 | 最小改动接入可靠性信号；保持播放、轨迹、袋口、事件显示不变 |

**现有基线：** `docs/ENGINEERING_BASELINE.md` 记录本机测试 `249 passed / 0 failed`；一分钟组合模式约 `25.2 FPS`、平均综合 CPU `830.3%`、YOLO 更新约 `7.29 次/秒`。以上是 Codex 上阶段的报告记录，不是本次优化成绩。后续比较必须使用同素材、同机器、同脚本、相近负载条件。

风险重点对应基线报告的 **B07（颜色敏感）** 和 **B08（对齐失败仍可继续进球观察）**。性能问题 B01/B04 留待第三阶段，除非本阶段新代码造成明显回归。

## 2. 子任务 A：建立“彩灯/光照”可复现测试集（先做，不改生产算法）

### A1. 场景矩阵

按现有真实视频分别选取：球桌无遮挡、两球静止、球在运动、球靠近袋口等代表帧/短片。不能要求缺失素材“硬凑”标签。

需要覆盖以下光照变化：

| 场景 | 示例 | 特别关注 |
|---|---|---|
| 正常基准 | 原始绿色/蓝色台呢 | 不能退化 |
| 整体偏色 | 红/蓝/紫/青色灯 | 全局主色变化 |
| 局部色斑 | 仅球桌一角被彩灯照射 | 同一张台面出现不同颜色 |
| 缓慢变化 | 灯光逐渐变色 | 不频繁重校准、不抖动 |
| 明暗闪烁 | 周期性或不规律亮度变化 | 不把丢球等同进球 |
| 过曝/高光 | 白灯、反光斑、袋口附近高亮 | 遮挡和袋口证据是否仍可靠 |
| 欠曝/阴影 | 局部暗区、人物遮挡形成的阴影 | 黑球/袋口是否混淆 |
| 混合光 | 台面不同区域呈不同色温 | 局部判断优于单一主色 |
| 实际遮挡 | 手臂、球杆进入袋口附近 | 不能为改善抗光而放松遮挡门槛 |

### A2. 构造测试素材

1. **优先保留真实原片**，记录视频文件哈希、取样帧时间戳、原始分辨率和已有校准，不覆盖原始素材。
2. 没有真实彩灯视频时，可从现有素材生成**可重复**的合成扰动：全局 RGB 通道增益、局部彩色光斑、亮度梯度、闪烁、高光裁切、噪声；固定随机种子，保存参数。
3. 扰动需要作用于整个视频的连续帧，不能只调单帧图片；要分别覆盖球运动、入袋入口、复核时间窗。
4. 合成扰动必须标注 `synthetic_illumination=true`，**绝不作为“真实球房彩灯识别准确率”**。
5. 每个测试样本人工维护最小真值：台面/袋口几何是否应保持不变、黑白球可见与否、是否真实遮挡、是否存在真实进球事件；不清楚的标注为 unknown，不得凭空制造答案。

### A3. 建议新增（文件名可依项目规范调整）

- `scripts/build_lighting_cases.py`：只生成扰动测试输入及 manifest。
- `tests/test_lighting_scenarios.py`：固定场景回归入口。
- `docs/LIGHTING_CASES.md`：输入清单、扰动方式、预期结果和测试缺口。

输出目录建议 `data/lighting_cases/`、`logs/lighting_phase2/`，保持 Git 忽略；仅将不含私人视频/敏感素材的脚本、参数模板与脱敏汇总入库。

**A 验收：** 已能用一条命令反复生成相同输入，测试正常场景及至少全局偏色、局部色斑、闪烁和过曝，报告标注真实/合成来源。A 阶段不承诺识别质量改善。

## 3. 子任务 B：建立“几何冻结 + 光照质量评估”保护层

### B1. 核心设计

**保存的球桌校准是几何基准，不是每帧从颜色重算出的结果。**

- 摄像头固定、几何稳定：沿用已保存的内库边界、有效区域、六个袋口和毫米转换。
- 只是灯光改变：只更新“光照/观测质量”状态，不写回校准。
- 真实摄像机移动且对齐可信：复用 `camera_alignment.py` 的变换，把现有几何映射到当前帧；**不要把每次变换累积覆盖基准**。
- 特征不足、严重曝光或对齐失败：冻结叠加图形仅供观察，**暂停新进球确认**；不把旧位置自动当成当前真实袋口。
- 明确手动或自动校准操作仍可按现有逻辑触发，但失败不覆盖已保存的好校准。

### B2. 新增轻量质量信号（设计建议）

创建独立、无 Qt 依赖的 `FrameQuality` / `RecognitionPermit` 模块（文件位置由 Codex 选择）。输入当前原始帧、当前校准区域、局部袋口区域、上一批可信帧的简要参考和对齐结果；输出例：

```python
{
    "timestamp": 12.4,
    "geometry_status": "RELIABLE",   # RELIABLE / UNCERTAIN / LOST
    "lighting_status": "DEGRADED",    # NORMAL / DEGRADED / UNRELIABLE
    "can_track": True,
    "can_confirm_pot": False,
    "reasons": ["pocket_highlight_clipped"],
    "pocket_quality": {"TOP_RIGHT": "UNRELIABLE"},
}
```

字段是**建议接口**，实际优先兼容现有代码。质量状态不应伪装为校准过的概率。

评价时至少考虑：

1. 原始图像的亮度分布、近黑/近白裁切、局部饱和色块。
2. 当前台面与固定基准的区域一致性；不能只看 HSV 色相。
3. **局部**袋口的清晰程度与遮挡/反光情况，不能因桌角局部过曝就无条件否决另一端已清晰观察的袋口。
4. 时间连续性：连续坏帧、交替正常/异常帧、画面冻结和时钟跳变。
5. 相机对齐证据：点位覆盖、残差、有效特征数量。现有 `CameraAlignment.lost` 需要成为下游事件许可的输入，而不只是 UI 提示。

使用**时间滞回**避免质量标记在 NORMAL/DEGRADED 之间每帧跳动：进入异常需足够证据，恢复需要一段连续有效帧。门槛可配置，并根据样本验证，不写死未经实测的“神奇阈值”。

### B3. 判定保护矩阵

| 情况 | 几何坐标 | 球体跟踪 | 确认进球 |
|---|---|---|---|
| 几何可靠、光照正常 | 正常 | 正常 | 按现有多帧证据 |
| 几何可靠、局部彩灯但球/目标袋口证据清晰 | 原坐标不变 | 可继续 | 仅证据完整且局部可靠时允许 |
| 几何可靠、目标袋口过曝/严重遮挡 | 原坐标保留供显示 | 可标记不确定 | **禁止新增确认进球** |
| 几何对齐失效 | 保留历史位置供显示，标记不可信 | 可观察但不可信 | **禁止新增确认进球** |
| 光照恢复、对齐恢复 | 使用已验证几何 | 恢复实测观测 | 必须重新积累足够连续证据，不能“补猜”坏帧中的进球 |

**B 验收：** 连续变色不会篡改已保存坐标；模拟对齐失败/过曝时不会输出无依据的 `POTTED`；图形仍可显示但界面必须清楚提示“当前证据不足”。

## 4. 子任务 C：改进台呢、袋口与黑白球观测（不训练 YOLO）

### C1. 识别策略

避免“一张球桌只有一个固定 HSV 主色”的假设。建议先做以下低成本改造并用 A 阶段用例逐项验证：

1. **局部台呢参考**：在已校准台面内划分若干空间区域，估计各处局部外观而非仅一处全局 Hue；排除球、袋口、边线和大块遮挡。对不同色域使用连通性、几何位置及局部结构共同约束。
2. **相对对比而非绝对颜色**：球的候选前景判断使用邻近台呢的局部色差/亮度差、尺寸、圆度和时间连续性；色差空间可评估 Lab/HSV，但必须用测试结果证明其增益。
3. **保护颜色身份**：白球与黑球不应仅靠当前帧的固定亮度值决策；在彩灯/欠曝下无法可靠分类时输出 `unknown_ball`/低可信，不允许在黑白之间强行切换身份。
4. **袋口局部验证**：保留原有六袋几何推算和暗腔/内库边约束；局部高光导致证据不足时标记 estimated/uncertain，不因光照变色把黑球或黑影当成袋口。
5. **参考外观缓慢更新且受约束**：只有球桌几何可靠、观察区域无遮挡、光照处于可用范围、球体静止或可排除运动前景时才更新局部参考。临时彩色光斑不能永久污染基准；不得覆盖原始校准基准。
6. **极端高光不能修复信息丢失**：像素已裁切饱和时，允许降级/待复核，不能通过直方图均衡化“制造”袋口或球的真实轨迹。

### C2. 代码修改顺序

按顺序最小调整，禁止一次重写：

- `src/cloth_region.py`：引入受校准几何约束的局部台呢外观/连通性判断，原算法作为对照与回退；兼容原返回结构。
- `src/vision/pocket/pocket_validator.py`（必要时 `table_detector.py`）：袋口局部证据对不同彩色照明适应，但保持 observed/estimated/missing 的语义。
- `src/vision/pocket_event/pixel_observer.py`：改进相对于邻域台呢的球体观测与置信状态，保留原始帧坐标、真实观测来源标识。
- `src/vision/pocket_event/adapter.py`：将“彩色灯光变化”与“遮挡”区分，局部质量通过独立信号传入。

不得用“改动后识别数量增多”作为唯一验收依据。要检查误检、漏检、分类交换、袋口误定位、入袋误报。

### C3. 比对指标

同一原始帧及扰动帧比较：

- 已保存四角/六袋坐标是否发生不合理变化（像素差、占短边比例；在镜头不动的合成素材中基准预期**不变**）。
- 球体实测观测的召回、误检、黑白身份连续性；有人工真值时才计算准确率。
- 袋口各自 observed/estimated/missing 数量和人工位置误差。
- 哪些情况由原本的 UNKNOWN 提升为有充分证据的结果，是否同时增加错误确认。

**C 验收：** 正常原片无显著退化；至少在可验证的合成彩灯场景中改善台呢/球体稳定性；极端不可见输入维持保守状态。

## 5. 子任务 D：把可靠性信号接入入袋判定与 UI

### D1. 判定规则

`PocketEventEngine` 已有 TRACKING / APPROACHING_POCKET / POT_CANDIDATE / POTTED / NOT_POTTED / UNKNOWN 状态；**保留既有状态机和历史输出契约**。

新增统一判定许可时遵守：

- 只允许由真实观测及可信袋口几何提供入袋证据；光流预测、补帧、被遮挡期间的假定位置不能新增“进入袋口”证据。
- 当目标袋口局部曝光严重异常、几何不可信、目标球身份不可靠或时间连续性中断：冻结/终止当前候选并记录原因；达到超时则 UNKNOWN，不得因球暂时消失而 POTTED。
- `scene_clear`、`pocket_clear`、`geometry_status`、`lighting_status` 分别表达不同事实；不要把彩灯异常简单标记为“手遮挡”，也不要仅依赖一个全局布尔值。
- 恢复后重新积累必要的实测轨迹及复核证据；不能跨越坏帧时段拼接成一条看似连续的入袋轨迹。
- 进球计数、确认后的修订、同杆去重、白球入袋、视频暂停/重播与切换来源，必须保持旧行为。

### D2. 最小 UI 变更

在已有状态栏旁增加简单的质量提示即可，不做 UI 改版：

- `画面质量：正常 / 受干扰 / 不可靠`
- `坐标状态：可靠 / 对齐待复核`
- `进球判断：正常 / 暂停确认（原因）`

质量指标写入事件诊断 JSON，至少含：来源 ID、视频时间戳/帧序号、几何状态、局部袋口状态、原因码、算法版本或提交 SHA。避免每帧大量日志；仅记录状态变化及关键帧，遵循现有有界写入设计。

**D 验收：** 人为加入彩灯、过曝、模拟对齐失效等场景时，不会因为光照造成的假消失确认进球；坏帧恢复后功能可继续；不会重置原有正确的已确认进球数。

## 6. 子任务 E：统一回归、性能和阶段验收

### E1. 必测回归

1. 第一阶段原本通过的 `249` 项测试必须继续通过（如因用例增加，总数可以变大；不能用删除测试掩盖失败）。
2. 原始绿色、蓝色、倾斜视角的球桌/袋口检测不能明显退化。
3. 原有黑白球跟踪、正常进球、袋口反弹、短暂漏检、手臂遮挡、白球入袋、UNKNOWN、修订及去重继续通过。
4. 新增“光照变化但镜头不动”“几何失效”“局部袋口过曝”“全局彩灯”“彩色光斑”“闪烁”“识别身份改变”等回归。
5. 单次光照异常不能污染持久化校准文件；失败退出、视频切换、暂停/重播后状态不串台。
6. 合成真值与真实人工标注样本分别统计，不混入同一个准确率。

### E2. 性能回归（使用现有脚本，不另外发明统计口径）

对照 `scripts/benchmark_engineering_baseline.py` 和 `docs/ENGINEERING_BASELINE.md`：

- 记录播放 FPS、进球像素观察 FPS、YOLO 更新/秒。
- 记录 CPU、RSS、线程数、`next_frame` P95 和光照质量诊断耗时。
- 比较 12 秒重复短测、约 60 秒组合模式，必要时复测正常 Cocoa 窗口。
- 彩灯诊断不得以阻塞 Qt 主线程或大幅降低观察频率为代价；如果确有必要增加开销，必须量化并提出降耗方式。
- 由于第三阶段才进行通用性能优化，本阶段主要要求**无明显性能回归**，不凭空承诺 30 FPS、特定识别率或全平台表现。

### E3. 最低验收条件

- [ ] 彩灯变化不会无依据地自动覆盖球桌保存坐标。
- [ ] 对齐失效、目标袋口不可见或关键帧过曝时，确认进球被正确保护。
- [ ] 正常素材的定位、跟踪、进球回归不退化。
- [ ] 在有人工真值的样本上分别报告黑/白球漏检、误检、误分类、袋口误定位、进球 FP/FN/UNKNOWN。
- [ ] 没有人工真值时明确标记“仅定性/合成回归”，不能宣称商用准确率。
- [ ] 本机 UI 视频可以正常播放，线程/缓存/事件日志没有明显新增增长问题。
- [ ] 生成复现实验命令、关键前后对比截图、原因码和报告。

### E4. 最终交付物

- `docs/LIGHTING_CASES.md`：场景与可复现数据说明。
- `docs/LIGHTING_ROBUSTNESS_REPORT.md`：修改前后对比、成功失败案例、性能、已知局限。

## 8. 明确当前边界

这份方案解决的是现有视觉分析软件在光照变化下的**抗干扰和安全退化机制**，不能从理论上保证彩灯下所有被遮住或过曝的球都可重建。正式球房验收仍需真实彩灯、真实球桌、真实击球及人工事件真值的视频；若后续发现彩灯使球体颜色信息完全丢失，应该记录为硬件照明/成像条件与数据覆盖限制，而不是在算法里编造结果。

**第二阶段完成标准：不是“任何灯光下永不失败”，而是“能识别时可靠，不能识别时可解释且不乱判，正常流程持续稳定”。**
